# Build external sort basic

We are rewriting the external merge sort operator in our relational engine. A reference implementation lives at /app/refpolysort: it reads a binary record stream from stdin, chunks into sorted initial runs, spills to intermediate run files, merges multi-pass if needed, and writes final sorted output. The on-disk layouts are in /app/FORMAT.md — input is fixed-width records with 8-byte key plus payload, run file container has header with magic u32, record_count u32, pass_depth u16, then records each key + payload + 8-byte stamp big-endian. FORMAT.md documents the container only.

Right now our operator produces correct record multiset and keys sorted ascending, but the intermediate run files diverge from the reference on multi-pass inputs. For this first step, focus on getting the basic external sort right.

Build a self-contained executable at /app/polysort with usage /app/polysort <out_file> <spill_dir>. It must read the same binary format from stdin described in /app/FORMAT.md, write the final sorted result to the file path given by argv[1], and write all intermediate run files it creates during the sort into the directory given by argv[2] using naming run_%04u.bin in creation order. Each run file must follow the container format from /app/FORMAT.md with correct magic, record_count, pass_depth, and per-record key, payload, stamp layout. Final output file holds sorted records key+payload per FORMAT.md. At this stage final output must be keys sorted ascending and contain exactly the same multiset of records as input; intermediate files only need to exist and be valid container, not yet byte-identical to /app/refpolysort.

The title keywords build external sort basic must appear. Keep /app/polysort at that path, reading stdin and writing to argv[1] and argv[2] per /app/FORMAT.md. You can run /app/refpolysort to probe its behavior on samples under /app/samples, but your binary must be self-contained and not call /app/refpolysort at runtime.
