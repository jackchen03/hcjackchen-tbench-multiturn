We have a small in-house storage engine that logs every mutation to a key/value table as an append-only binary transaction log. Ops replays the log to rebuild the table's final committed state. The rebuild is producing wrong results.

Symptom: an order transaction deletes and then mutates several rows mid-checkout, commits successfully, but the rebuilt table still counts rows the customer removed during checkout. At the same time, transactions that never finished and were abandoned have their writes leaking into the final result. The log itself looks perfectly regular if you run `od` or `hexdump` — every record decodes cleanly, so staring at the hex does not show what is over- or under-counted.

You have a reference replayer at `/app/gold_replay`, usage `/app/gold_replay <log_file> <output_file>`. It writes the true final committed state for any log you give it. You can build arbitrary logs and feed them to it to learn how it adjudicates sequences, especially repeated rollbacks inside the same transaction and whether a transaction ends up committed or abandoned. The byte layout is documented in `/app/FORMATS.md` there with only minimal gloss per record type — treat actual `/app/gold_replay` behavior as ground truth. Samples live in `/app/samples/`, each `.log` has a correct `.out` produced by `gold_replay`.

Deliver an executable at `/app/replay`, usage `/app/replay <log_file> <output_file>`: read the binary log, compute the table's true final committed state, and write it to `<output_file>`. Output format is one live key per line as `<key> <value>` (both decimal integers, single space), sorted ascending by key, each line terminated by `\n`, no header or extra content. Do not emit deleted or non-live keys; if the final table is empty, output an empty file. Grading will use logs whose key/value ranges do not overlap samples, and `/app/gold_replay` plus `/app/samples` will be removed, so your program must implement the adjudication logic fully — it must not invoke `gold_replay` at runtime and must not hardcode sample results.
