We reconcile end-of-day positions against the exchange FIX drop-copy — cumulative vs incremental fill reconciliation. The exchange side drops every ExecutionReport (35=8) for the day into a file with cumulative CumQty; we have an internal ledger that accounts incremental fills. The reconciler lives at `/app/reconcile.py` and is run as `python3 /app/reconcile.py <dropcopy_file> <output_json>` — it reads the drop-copy and rebuilds net position per symbol (buy positive, sell negative, in shares) and writes it to the output path given on the command line. This is the core fill reconciliation bug: cumulative quantity vs incremental fills across cancel/replace chains.

Lately the nightly run is off by about one child order size on a few symbols, while other symbols tie perfectly. If you open the ExecutionReports one by one, every CumQty, LastQty, AvgPx looks fine in isolation. Those symbols mostly went through cancel/replace (new order via OrigClOrdID chaining back to the original) and we receive fills from multiple venues at the same time, and the failures cluster on those names.

A sample drop-copy is at `/app/sample/dropcopy.fix` with its correct net position at `/app/sample/expected.json` that you can use to check.
