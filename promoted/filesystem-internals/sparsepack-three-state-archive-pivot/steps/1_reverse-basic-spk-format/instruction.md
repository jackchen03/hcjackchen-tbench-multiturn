We lost the source for our internal backup tool `sparsepack` — only a runnable binary remains at `/app/reference/sparsepack`. It takes an ext4 image and an inode number: `sparsepack <image> <inode>` writes an archive to stdout (`sparsepack disk.img 12 > out.spk`). You can query it on any image you create.

Under `/app/samples/` there are several small sample images `*.img` and some archives `*.spk` produced by the reference on a few inodes for reference. The system has `e2fsprogs` (`mke2fs`, `debugfs`, `dumpe2fs`) for unprivileged inspection without mount.

Your job this step: figure out the binary layout and write your own version at `/app/mysparsepack` with the same CLI `mysparsepack <image> <inode>` writing the archive to stdout. For now focus on small files that fit in a single-level extent tree (<=340 extents) and only exhibit two states — hole and written — no  extents, no written-zero blocks. On those, the reference uses header magic `SPK1` (4 bytes), little-endian `u32` inode number, `u64` file size from `i_size`, `u32` record count, then records in ascending logical-block order each with `type u8`, `start_block u32`, `block_count u32`, optional payload, and trailer `final_crc u32`. Written records carry a running `CRC-32` snapshot (IEEE, zlib compatible) over written bytes in logical order; the trailer is the final rolling checksum.
