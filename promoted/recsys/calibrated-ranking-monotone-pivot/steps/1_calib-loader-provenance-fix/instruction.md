Our recsys ranking service under /app has a calibrated ranking issue. The pipeline is: for each user, each candidate item gets a base score from a frozen model, then multiplied by a per-bucket calibration weight looked up via a continuous feature bucketed into bins. Final score sorted descending, tie broken by item_id ascending. Running `python -m rec.serve` writes `/app/output/rankings.csv`.

The problem: online rankings don't match offline evaluation. Top item is usually right but positions 3-8 mid-list are permuted, and NDCG@10 drops online vs offline. If you print the calibration weights from disk they all look present and plausible magnitude — no missing values. Single-file inspection of code, table, or artifact alone doesn't show it.

Your first task is to investigate the calibration loading path. The binary artifact is at `/app/artifacts/calibration.bin` and its record layout is documented in `/app/artifacts/FORMAT.txt`. The training script that produced it lives at `/app/rec/train_calib.py`. Focus on why the online serving path might be using the right values but attached to the wrong buckets, causing the calibrated ranking scores to be monotone-correct in value set but positionally shuffled for mid-range items — the non-monotone calibration curve makes a simple sort of the table incorrect.

After fixing, running `python -m rec.serve` must write `/app/output/rankings.csv` with exact header `user_id,item_id,rank`, each user 10 rows, rank 1..10 descending final score, tie `item_id` asc. Don't edit base ranker weights in `/app/rec/rank.py`, training data under `/app/data/`, bin edges in `/app/data/edges.json`, or the artifacts themselves under `/app/artifacts/`. Only fix serving logic. The output contract is critical for grading, and more steps will follow after this fix.
