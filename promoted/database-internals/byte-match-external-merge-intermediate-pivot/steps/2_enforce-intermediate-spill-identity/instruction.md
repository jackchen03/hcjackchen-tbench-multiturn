# Enforce intermediate spill identity

Your previous /app/polysort sorts the final output but its intermediate spill files don't match the reference bytes on multi-pass inputs. Downstream checker does a byte-for-byte diff of both final output and every intermediate run file. Small inputs that fit in one pass already match, but once run count exceeds fan-in and the engine does cascading merges, the intermediate bytes diverge — same record multiset, keys sorted, but equal-key order and run file contents differ.

Tighten your existing binary at the same path /app/polysort with same invocation /app/polysort <out_file> <spill_dir> reading stdin binary stream per /app/FORMAT.md. Don't re-derive the run file container from scratch; you already have the area and conventions. Now for any input, the final output file and every file in the spill dir must be byte-for-byte identical to what /app/refpolysort produces under the same call — file count, names run_%04u.bin in global creation order, each file's magic, record_count, pass_depth header and each record's key, payload, stamp bytes identical. That includes all intermediate passes, not just the final merge. Keep using /app/FORMAT.md for container layout only; the merge grouping, stamp propagation, and equal-key tie-break are not in FORMAT.md and must be recovered by probing /app/refpolysort on different sizes and diffing the run files with od.

The title keywords enforce intermediate spill identity must appear. Keep /app/polysort self-contained, preserve the spill directory convention and run_%04u.bin naming you used before.
