The three-node shard simulator keeps accepting writes while a shard changes owner, but some admitted commands disappear or run twice when delivery crosses the cutover. Make live handoff preserve every completed non-commutative effect exactly once and return the original reply on a retry. Unrelated shards must remain writable throughout.

Admission happens before delivery and issues a ticket containing the shard generation and the full client identity `(incarnation, sequence)`; the same sequence is legal again under a different incarnation. A command may arrive after the shard generation changes. Durable effect application and durable reply acknowledgement are separate frontiers, and both must survive ownership movement. Preserve the existing `shardsim` command line and JSONL trace contract described in the starter tree.
