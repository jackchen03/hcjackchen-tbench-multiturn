We have an internal formatter that writes test filesystem images. The original binary is at /app/reference/myfs-mkfs — you can run it freely to probe its behavior. It is used as `myfs-mkfs <output image path> <size MiB> <stride> <flex>` where the four args are output file, total image size in MiB, a stride alignment parameter, and a flex grouping parameter. Check /app/samples/ for a few specs and the images that the original produces for them. The container has e2fsprogs (dumpe2fs, debugfs), mtools, python3 and sqlite3 — all work on the .img file without mounting, no root, no loop or fuse.

For this step, build your own formatter at /app/mymkfs with the identical CLI: `/app/mymkfs <output image path> <size MiB> <stride> <flex>`. Focus on getting the STRIDE=1 cases byte-identical first. That means your binary must produce clusters of metadata grouped at the start of each flex group, no sparse backups, fixed superblock constants and root directory layout that exactly match what the reference writes when stride is 1. You can probe the reference on arbitrary STRIDE=1 sizes and flex values, parse the superblock at offset 1024 and the GDT with dumpe2fs, and compare bytes.

More steps follow, so conserve the probe scripts you write.
