We have a multi-threaded quote/order gateway at /app/gateway.py. It replays a tick event stream in JSONL format where each line is one event: {"oid":int,"sym":str,"side":"BID"|"ASK","price":int,"qty":int,"action":"ADD"|"TAKE"}. ADD rests an order at (sym,side,price), TAKE is an incoming marketable order that sweeps the resting queue at that (sym,side,price) for qty. The gateway is invoked as python3 /app/gateway.py <feed_file> <output_file> and writes all fills as a JSON array of {"taker":oid,"maker":oid,"price":int,"qty":int} in execution order.

Recently replaying high-frequency feeds shows a subtle bug: at the same price level where many makers rest, the fill order is wrong — a later arriving maker fills before an earlier arriving one, sometimes stealing quantity that should have gone to the earlier order. With tiny feeds or when forcing the thread pool to one worker, results look perfect. Under realistic-rate large replay with heavy same-price clustering, inversions appear intermittently. The program never errors and never drops events.

For this first step, narrow scope to single-symbol, single-price cases: focus on feeds where `sym` is constant (e.g., only AAPL) and `price` is constant at a single level, with heavy same-price clustering causing the inversion. Check /app/sample/feed.jsonl (which for this step is single-symbol single-price) and its correct result /app/sample/expected_fills.json for format and semantics. Fix the gateway so that for single-symbol single-price feeds, at that price level makers fill strictly in arrival order (arrival = feed line order), and repeated runs on the same feed are stable. Keep output format unchanged: JSON array of {"taker","maker","price","qty"} in execution order. Multi-symbol and multi-price handling will be extended in the next step, so do not yet require strict priority across all symbols/sides/price levels in this step — only single-symbol/single-price.

We will test with additional feeds using disjoint order ids and prices from the sample, but still single-symbol/single-price for this step, so do not hardcode the sample.
