We have a set of ext4 filesystem images that are just regular files — not mounted block devices. On a privileged host we loop-mounted each image and, for every file inside, ran `lseek` with `SEEK_HOLE` and `SEEK_DATA` over a fixed list of byte offsets, recording what the kernel returned. Those traces are the ground truth.

In this container we cannot mount, have no root, no loop device, no `fuse` — the image must be treated as a raw byte file you read yourself. Samples to self-check are in `/app/samples/` : each contains `image_*.img`, `queries_*.txt`, and `expected_*.txt`. The `queries_*.txt` file has one query per line with three space-separated columns: first is the absolute path inside the image (e.g. `/file1`), second is a decimal byte offset, third is `DATA` or `HOLE` meaning `SEEK_DATA` or `SEEK_HOLE` at that offset. Some offsets are at or past end-of-file. For each query you must output one line: if `lseek` would return an offset, output that decimal offset; if it would fail with `ENXIO`, output the literal `ENXIO`. Output lines must be in strict one-to-one order with queries. `expected_*.txt` is in that exact format.

Build an executable script at `/app/run.sh` invoked as `/app/run.sh <image_path> <queries_file> <output_file>` : it reads the given image and queries file and writes per-line results to the given output file. For this step focus on plain sparse files with interior holes — the tool must match the kernel's `SEEK_HOLE`/`SEEK_DATA` on those, not a content-based zeros scan. Grading runs your `/app/run.sh` on unseen images/queries and diffs it line-by-line against hidden ground truth — must be exact. Keep `seek`, `hole`, `data`, `kernel`, `match` logic correct for sparse extent maps.
